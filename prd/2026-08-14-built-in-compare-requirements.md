# FilemanElectron 内置对比功能 PRD

> 文档状态：Draft v0.1
> 创建日期：2026-08-14
> 产品阶段：既有能力产品化升级
> 适用平台：macOS / Electron 29
> 对标产品：Beyond Compare 5（借鉴工作流，不复刻完整功能集）
> 文档关系：本 PRD 作为对比功能的最新产品范围基线；`docs/superpowers/specs/2026-03-22-directory-compare-design.md` 保留为既有目录比较设计与实现历史，冲突处以本 PRD 为准

## 1. 文档摘要

FilemanElectron 已具备目录比较、Monaco 文本 Diff、图片并排/滑动/叠加/像素差异等基础能力，但入口、跨设备支持、比较准确性、安全操作和跨文件导航尚未形成统一产品闭环。

本期目标是在文件管理器内提供一套接近 Beyond Compare 核心体验、但更轻量且更安全的内置对比功能：用户选中两个文件夹、文本文件或图片后，可直接打开统一对比标签页；文件夹对比承担总览和导航职责，双击条目进入文本或图片子比较；对比默认只读，涉及覆盖的复制操作必须明确方向和影响范围。

首版不追求复刻 Beyond Compare 的全部同步、脚本、远程配置和三方合并能力，而是优先解决三件事：

1. 快速、明确地看出两侧差异。
2. 在文件夹总览和单文件细节之间连续工作。
3. 安全地采用左侧或右侧内容，不产生误覆盖或误删。

## 2. 背景与问题

### 2.1 用户问题

FilemanElectron 的核心使用场景包含本地、SMB、SSH/SFTP、WebDAV、Android、iOS 等多来源文件管理。用户在复制、备份、发布、迁移或清理文件前，经常需要回答：

- 两个目录是否真的一致？
- 哪些文件只存在于一侧？
- 同名文件是内容不同，还是只有时间戳不同？
- 两个文本版本具体改了哪些行、哪些字符？
- 两张图片只是压缩或色彩存在轻微差异，还是视觉内容发生了变化？
- 看完差异后，如何安全地把正确版本复制到另一侧？

现有能力已经能覆盖部分问题，但用户需要先进入目录比较，单文件对比缺少直接入口；目录快速规则与内容完全一致的语义容易混淆；文本和图片对比缺少统一的父子导航及部分关键控制。

### 2.2 对标启示

Beyond Compare 的关键优势不是单一 Diff 算法，而是：

```text
文件夹差异总览
  → 打开具体文本/图片差异
  → 上一组/下一组差异文件
  → 采用一侧内容
  → 返回文件夹后继续处理
```

FilemanElectron 应复用这一工作模型，同时减少工具栏密度、过滤器歧义和高风险同步操作。

## 3. 产品目标与非目标

### 3.1 产品目标

| 编号 | 目标 | 判断标准 |
|---|---|---|
| G1 | 统一入口 | 任意可读来源的两个同类对象，可在文件列表或双面板中直接发起对比 |
| G2 | 清晰表达差异 | 所有状态同时使用颜色、图标和文字，不依赖颜色单独传达 |
| G3 | 形成跨层级闭环 | 文件夹对比可进入文本/图片子比较，并连续浏览上一/下一组差异文件 |
| G4 | 避免“假相同” | 明确展示当前比较依据；按元数据相同不得伪装成“内容已验证相同” |
| G5 | 安全采用内容 | 复制方向、覆盖目标和受影响数量必须明确；失败不得破坏源文件 |
| G6 | 适配多来源 | 对比逻辑建立在 `IFileSystemAdapter` 之上，不限定本地文件系统 |

### 3.2 成功标准

本项目暂不新增用户行为遥测，成功标准通过产品验收和回归测试判断：

- 三类对象均能从文件管理主界面直接进入正确比较器。
- 用户无需阅读帮助即可区分“仅左侧”“仅右侧”“不同”“左侧较新”“右侧较新”。
- 文件夹比较中的任意成对文本/图片可在两次操作内进入细节比较。
- 关闭子比较后，父文件夹比较保留原滚动位置、过滤条件和选中项。
- 任意覆盖操作执行前，用户都能确认来源、目标和影响数量。
- 设备断连、权限不足、文件变化或解码失败均显示可理解错误，不出现空白页或静默失败。

### 3.3 非目标

本期不做：

- 三方文本合并、三方文件夹合并。
- 自动双向同步和镜像删除。
- FTP/SFTP/WebDAV 账号管理；沿用 FilemanElectron 现有设备连接能力。
- 一张图片对一个目录的相似图片搜索。
- 二进制 Hex Diff、表格语义 Diff、PDF 视觉 Diff、Office 文档转换。
- 命令行脚本、补丁生成、HTML 报告。
- Beyond Compare 式可共享具名会话系统。
- 文本编辑与保存；P0 文本对比保持只读。

## 4. 目标用户与核心场景

### 4.1 目标用户

| 用户 | 主要目标 | 典型来源 |
|---|---|---|
| 开发者 | 比较代码、配置、构建产物和版本目录 | 本地、SSH、SMB |
| 设计/内容人员 | 比较图片版本、导出图和资源目录 | 本地、移动设备、网络盘 |
| 文件整理用户 | 验证备份、迁移、重复目录和设备文件 | 本地、WebDAV、Android、iOS |

### 4.2 核心场景

#### 场景 A：发布目录核对

用户在双面板分别打开旧版本与新版本目录，点击“对比”后看到新增、删除、修改和时间较新的文件；双击代码文件查看行级差异，确认后将选中文件复制到另一侧。

#### 场景 B：两个文本文件直接比较

用户在同一列表选中两个配置文件，右键“对比”，进入 Monaco Diff；通过上一处/下一处差异快速检查，并可切换并排或内联布局、忽略尾随空白。

#### 场景 C：图片版本检查

用户选中两张图片，进入图片对比，依次使用并排、滑动、叠加和差异模式；调整透明度、容差和缩放，判断图片是否存在实质变化。

#### 场景 D：跨来源校验

用户在左面板打开本地备份，右面板打开 SMB、SSH 或移动设备目录，发起对比。比较过程显示来源设备、进度和失败项；设备断连后可重试，不丢失父会话上下文。

## 5. 术语与业务对象

| 术语 | 定义 |
|---|---|
| 对比对象 | 用户选定的左侧与右侧文件或目录 |
| 对比会话 | 一次对比的路径、设备、类型、规则、过滤器和运行状态；P0 仅在标签页生命周期内存在 |
| 父会话 | 文件夹对比会话，负责维护成对文件列表与导航上下文 |
| 子比较 | 从文件夹条目打开的文本、图片或元数据对比 |
| 快速比较 | 主要依据名称、类型、大小和修改时间判断，速度快但不代表内容已验证 |
| 内容验证 | 通过流式逐字节或可靠摘要验证文件内容是否一致 |
| 差异项 | 状态不是当前规则下“相同”的条目 |
| 孤立项 | 仅左侧或仅右侧存在的条目 |
| 差异块 | 文本中连续的一组插入、删除或修改行 |
| 容差 | 图片像素差值不超过该阈值时，视为可忽略差异 |

## 6. 当前能力基线与产品缺口

| 模块 | 当前能力 | 主要缺口 |
|---|---|---|
| 目录比较 | 已有左右对齐列表、懒加载子目录、状态过滤、上一/下一差异、复制方向、状态统计 | 比较实现实际只使用左侧设备；缺少内容验证、过程状态、清晰比较依据和父子导航 |
| 发起入口 | 同一文件列表选中两个目录可右键“对比目录” | 文本/图片不能直接发起；双面板各选一个对象的入口未闭环 |
| 文本比较 | 已使用 Monaco Diff，支持并排/内联、语法高亮、差异导航；只读 | 仅能从目录对比进入；缺少空白规则切换、差异概览、文件级导航和重载 |
| 图片比较 | 已有并排、滑动、叠加、像素 Diff，显示尺寸和差异比例 | 固定像素阈值；缺少可调容差、同步平移、偏移校准、重载和父会话导航 |
| 标签页 | 目录和文件 Diff 使用独立临时标签页 | 子比较未显式引用父会话，无法可靠“上一组/下一组差异文件” |
| 文件操作 | 目录对比中已可向左/右复制，并复用文件操作队列 | 批量/覆盖影响范围提示不统一；过滤后的隐藏子项可能造成理解歧义 |

本 PRD 的需求优先覆盖上述缺口，不重复建设已经可用的比较视图。

## 7. 信息架构与导航

### 7.1 对比类型路由

系统根据两个对象自动选择比较器：

```text
两个目录                 → 文件夹对比
两个可识别文本文件       → 文本对比
两个可解码图片           → 图片对比
其他两个文件             → 元数据对比 / 提示暂不支持内容对比
目录 + 文件              → 拒绝发起，提示必须选择同类对象
```

允许不同扩展名的同类对象比较，例如 `.jpg` 对 `.png`、`.js` 对 `.txt`；比较类型依据可解码能力和文件内容类别，而不是要求扩展名完全相同。

### 7.2 父子关系

- 从文件夹对比打开的单文件比较必须保存 `parentCompareSessionId` 与当前 `relativePath`。
- 子比较工具栏提供“上一组差异文件”“下一组差异文件”。
- 导航时复用当前子比较标签页，不连续创建新标签。
- 关闭子比较后回到父标签页，并恢复父列表滚动位置和选中项。
- 父文件夹会话关闭时，已打开的子比较仍可独立查看，但文件级上一/下一导航禁用并提示父会话已关闭。

### 7.3 标签页策略

- 每次直接发起对比默认新建一个标签页。
- 若相同左右对象和比较类型已经打开，则激活已有标签页并询问是否重新加载，不重复创建。
- P0 对比标签页不跨应用重启持久化。
- 标签标题格式：
  - 文件夹：`左目录名 ↔ 右目录名`
  - 文件：`文件名 · 对比`
- 标签图标使用文件夹、文本或图片类型图标；不要仅用 `=`、`≠` 作为标题前缀。

## 8. 发起入口与前置校验

### 8.1 同一文件列表

用户在同一列表恰好选中两个对象时：

- 右键菜单显示“对比”。
- 工具栏“对比”按钮可用。
- 快捷键 `⌘⇧D` 发起对比。
- 第一个被选中的对象作为左侧，第二个作为右侧；进入后可交换两侧。

### 8.2 双面板

当当前标签页为双面板，且左右面板各选中一个对象时：

- 顶部工具栏显示可用的“对比”按钮。
- 左面板对象固定为左侧，右面板对象固定为右侧。
- 对象可来自不同设备，只要两侧都具备读取能力。

### 8.3 拖放入口（P1）

- 将一个文件或目录拖到已打开对比页的左侧或右侧路径区，可替换该侧对象并重新比较。
- 拖入对象类型不兼容时，保持原对象不变并给出原因。

### 8.4 前置校验

发起前必须校验：

- 恰好两个对象。
- 两者是同类目录，或属于兼容的文件内容类别。
- 两侧设备在线且路径存在。
- 两侧设备均支持读取。
- 文件大小是否超过当前内置查看器限制。

校验失败不得打开空白对比页；错误提示应包含失败侧、路径和可操作建议。

## 9. 统一对比外壳

三类比较器共享以下结构和交互：

### 9.1 顶部栏

从左到右为：

1. 返回父对比（仅子比较显示）。
2. 左侧来源：设备名、路径、文件大小/修改时间摘要。
3. 交换两侧。
4. 当前结果摘要。
5. 右侧来源。
6. 上一差异、下一差异。
7. 重新加载。
8. 更多设置。

低频能力进入“更多设置”，避免复制 Beyond Compare 的密集大图标工具栏。

### 9.2 来源标识

- 左侧始终使用“左”文字标签，右侧始终使用“右”文字标签。
- 路径旁显示设备名或设备图标，避免跨设备时误判来源。
- 路径截断时，悬停显示完整设备名和路径。
- 交换两侧后，比较结果和复制方向同步更新。

### 9.3 结果状态

结果不得只使用颜色表达，必须显示文字：

- 内容相同。
- 元数据相同，内容未验证。
- 内容不同。
- 左侧较新。
- 右侧较新。
- 仅左侧存在。
- 仅右侧存在。
- 类型不一致。
- 无法比较。

### 9.4 运行状态

统一支持：

- 等待开始。
- 正在读取。
- 正在比较。
- 部分结果可用。
- 已完成。
- 已取消。
- 部分失败。
- 完全失败。

耗时操作必须可取消，取消后保留已经产生的只读结果，并明确标记“结果不完整”。

## 10. 文件夹对比需求

### 10.1 布局

文件夹对比使用左右镜像列表：

```text
┌──────────────────────────────────────────────────────────────┐
│ 对比规则  过滤器  内容验证  交换  上一差异  下一差异  刷新   │
├──────────────────────────┬───────────────────────────────────┤
│ 左设备 · 左根路径         │ 右设备 · 右根路径                  │
├──────────────────────────┼────────┬──────────────────────────┤
│ 名称 / 大小 / 修改时间    │ 状态   │ 名称 / 大小 / 修改时间     │
│ …                        │ …      │ …                         │
├──────────────────────────┴────────┴──────────────────────────┤
│ 差异 12 · 仅左 3 · 仅右 2 · 相同 80 · 隐藏 7 · 失败 1        │
└──────────────────────────────────────────────────────────────┘
```

### 10.2 配对规则

P0 采用相同相对路径和文件名配对：

- 默认不区分 Unicode 组合形式差异，macOS NFD 与其他平台 NFC 应能配对。
- 文件名大小写是否敏感跟随两侧文件系统能力；跨不同敏感度文件系统时，冲突项标记为“名称冲突”，不得自动任选其一。
- 同相对路径下文件与目录类型不一致时，状态为“类型不一致”。
- P0 不做忽略目录结构、不同文件名自动相似匹配或一对多配对。

### 10.3 比较模式

#### 快速比较（默认）

依据名称、类型、大小和修改时间：

- 修改时间差绝对值不超过 2 秒时视为时间相同，以兼容跨文件系统时间精度。
- 大小和时间相同显示“元数据相同，内容未验证”。
- 大小不同显示“内容不同”。
- 大小相同但时间不同显示左侧较新或右侧较新。

#### 内容验证

- 用户可对选中项或当前所有可见文件执行“按内容验证”。
- 内容验证必须流式进行，不得将大文件一次性加载到 Renderer 内存。
- 验证通过后状态升级为“内容相同”。
- 验证不通过后状态为“内容不同”；时间新旧仍作为辅助信息展示。
- 内容比较中的条目显示进行中状态，其他条目仍可浏览。
- 远程或移动设备比较必须显示进度并支持取消。

### 10.4 状态模型

| 状态 | 显示要求 | 是否属于差异 |
|---|---|---|
| 内容相同 | 对勾 + “内容相同” | 否 |
| 元数据相同 | 空心对勾 + “未验证内容” | 默认否，但可单独筛选 |
| 内容不同 | `≠` + “内容不同” | 是 |
| 左侧较新 | 左箭头 + “左侧较新” | 是 |
| 右侧较新 | 右箭头 + “右侧较新” | 是 |
| 仅左侧 | 左侧填充 + “仅左侧” | 是 |
| 仅右侧 | 右侧填充 + “仅右侧” | 是 |
| 类型不一致 | 警告图标 + “类型不一致” | 是 |
| 比较中 | 进度图标 + “比较中” | 未完成 |
| 读取失败 | 错误图标 + “读取失败” | 是 |

目录行显示子树汇总状态；未展开且未扫描的目录必须标记“未扫描”，不能提前显示为相同。

### 10.5 展开与扫描

- 初始加载根目录第一层，避免启动时递归扫描整个目录树。
- 展开目录时懒加载其子项。
- “扫描全部”递归处理所有子目录，并显示整体进度与取消按钮。
- 折叠目录不得丢弃已经获取的结果。
- 刷新默认只刷新当前已扫描范围；“完整刷新”放入更多菜单。

### 10.6 过滤与统计

P0 快捷过滤器：

- 全部。
- 仅差异。
- 仅左侧。
- 仅右侧。
- 内容不同。
- 相同/元数据相同。
- 失败项。

要求：

- 顶部始终显示当前过滤器摘要。
- 状态栏显示“已隐藏 N 项”，点击可清除过滤器。
- 目录行仅在自身或后代存在可见项时显示。
- 文件操作默认只作用于明确选中的可见条目；不得因选中目录而静默包含被过滤隐藏的后代。

名称、扩展名、大小、时间过滤放入 P1。

### 10.7 行交互

- 单击：选择整行，左右对应项同步高亮。
- `⌘`/`Shift`：遵循现有 Finder 式多选。
- 双击目录：展开或折叠。
- 双击成对文件：打开自动识别的文本、图片或元数据子比较。
- 双击孤立文件：打开单侧预览式比较，另一侧显示“无文件”。
- `F7` / `Shift+F7`：下一/上一差异项。
- 右键：打开对比、验证内容、复制到左/右、在文件管理标签页显示、查看信息。

### 10.8 复制与采用内容

P0 支持：

- 将左侧选中项复制到右侧。
- 将右侧选中项复制到左侧。
- 单个文件、多个文件及目录复制。
- 复用现有文件操作队列和进度面板。

安全要求：

- 按钮和确认框必须写明方向，例如“复制 4 项到右侧”。
- 目标存在同名对象时，先展示冲突数量，再选择覆盖、跳过或保留两者。
- 多选或目录操作执行前显示影响范围摘要。
- 复制完成后只刷新受影响条目，并更新比较状态。
- 复制失败不得修改或删除源文件。
- P0 不在对比页提供删除、镜像或自动双向同步。

## 11. 文本对比需求

### 11.1 支持范围

- 支持现有文本与代码类型识别列表。
- 允许不同文本扩展名互相比较。
- 默认按 UTF-8 解码；遇到 BOM 时按 BOM 处理。
- 无法可靠解码时显示编码错误，并允许在 P1 中手动选择编码。
- P0 保留 10 MB 单文件交互查看保护值；超过限制时显示元数据、大小限制原因和“使用外部应用打开”。

### 11.2 布局与差异表达

- 默认左右并排，支持切换内联模式。
- 两侧同步滚动并保持行对齐。
- 同时展示行级与行内字符差异。
- 插入/删除产生的空白对齐区必须清楚区分于真实空行。
- 显示文件名、设备、完整路径、大小、修改时间和语言模式。
- 提供可点击的差异概览轨道；P0 可使用 Monaco overview ruler，不强制启用完整 minimap。

### 11.3 工具栏能力

P0：

- 上一处/下一处差异块。
- 并排/内联切换。
- 忽略/计入尾随空白与空格差异。
- 显示/隐藏空白字符。
- 自动换行。
- 重新加载。
- 交换两侧。
- 返回父文件夹对比。
- 上一组/下一组差异文件（存在父会话时）。

P1：

- 忽略大小写。
- 选择文本编码。
- 只显示差异及上下文。
- 查找。
- 将差异块复制到另一侧并保存。

### 11.4 只读原则

- P0 Monaco Diff 两侧均只读。
- 文本内容的“采用左侧/右侧”只允许整文件复制，沿用统一覆盖确认。
- 差异块级编辑、保存、撤销和备份属于 P1，不与 P0 混合上线。

## 12. 图片对比需求

### 12.1 支持范围

P0 至少支持当前可解码的 PNG、JPEG、GIF 首帧、WebP、BMP、SVG、ICO；HEIC/HEIF 依据当前解码服务能力决定，解码失败时给出明确提示。

图片大小限制不能只按压缩文件体积判断，还需要根据解码后的像素尺寸评估内存风险。超过安全限制时显示元数据和外部打开入口，不触发 Renderer 崩溃。

### 12.2 查看模式

P0 保留并产品化现有四种模式：

| 模式 | 用户目标 | 核心交互 |
|---|---|---|
| 并排 | 独立观察两张图 | 同步缩放、同步平移、适应窗口、1:1 |
| 滑动 | 查看同一位置前后变化 | 拖动分割线；保持两图相同缩放与偏移 |
| 叠加 | 观察错位和细微变化 | 调整右侧透明度 0–100% |
| 差异 | 定位像素变化 | 可调容差、显示差异比例和差异像素数 |

### 12.3 对齐与视口

- 鼠标滚轮缩放；`⌘`/`Ctrl + 滚轮` 的现有行为可保留，但界面需提供可发现的缩放控制。
- 支持拖拽平移；两侧默认同步。
- 提供“适应窗口”“实际大小”“重置视图”。
- 两图尺寸不一致时，以透明空白区域补齐，不得隐式拉伸到相同尺寸。
- P1 支持 X/Y 偏移校准和重置偏移。
- P1 支持 90° 旋转和水平/垂直翻转，仅影响比较视图，不修改原文件。

### 12.4 像素差异

- 容差范围为 0–255，默认值 15，调整后即时重新计算。
- 差异判断至少考虑 RGBA；透明像素必须使用棋盘格表达。
- 差异视图中：未变化区域降饱和显示，超过容差的像素使用高对比色标记。
- 显示“差异像素数 / 总像素数 / 百分比”。
- 两图尺寸不一致产生的区域计为差异，并单独提示“尺寸不同”。
- 大图计算不得长期阻塞主线程；计算中显示进度或忙碌状态，可切换回其他查看模式。

### 12.5 元数据

P0 显示：

- 图片像素尺寸。
- 文件大小。
- 文件格式。
- 修改时间。

P1 显示可折叠的 EXIF 对照，包括拍摄时间、方向、相机、色彩空间等；元数据差异不默认计入视觉内容差异。

### 12.6 文件级操作

- P0 图片对比只读，不提供图片编辑。
- 支持整文件复制到另一侧，使用统一覆盖确认。
- 存在父文件夹会话时支持上一组/下一组差异图片。

## 13. 异常、边界与恢复

| 场景 | 期望结果 |
|---|---|
| 对象在比较前被删除 | 阻止进入并指出失效侧；提供重新选择 |
| 比较过程中对象被修改 | 标记“源文件已变化”，停止使用旧结果；允许重新加载 |
| 设备断连 | 保留当前结果快照，禁用读取和复制；重连后可重试 |
| 无读取权限 | 对应侧显示权限错误；不把空列表当作空目录 |
| 子目录读取失败 | 保留其他结果，将失败目录标为错误并支持单独重试 |
| 两侧同一路径 | 允许比较但提示“正在比较同一对象”；结果应为相同，不执行无意义复制 |
| 文件与目录同名冲突 | 标记类型不一致，不自动展开或复制覆盖 |
| 文本编码失败 | 显示编码错误与外部打开入口；P1 可选择编码重试 |
| 图片解码失败 | 显示格式/解码错误，不生成错误的 0% 差异结论 |
| 文件过大 | 显示限制原因和元数据；不读取完整内容到 Renderer |
| 内容验证取消 | 已完成项保留，未完成项恢复“未验证内容” |
| 覆盖复制失败 | 不修改源文件；目标半成品按文件操作队列规则清理 |
| 父会话关闭 | 子比较仍可查看；文件级上一/下一导航禁用 |

任何 `listFiles`、`readFile` 或内容比较异常都不得用空数组/空字符串静默吞掉并继续得出“相同”结论。

## 14. 非功能要求

### 14.1 性能

- 所有目录扫描、远程读取、内容验证和图片差异计算必须异步执行。
- 大目录采用渐进式结果：先展示第一层和已完成条目，再补充状态。
- 列表继续使用虚拟滚动；展开、过滤、选择不得导致整棵树高频序列化。
- 内容验证采用流式或分块读取，禁止将大文件完整 Base64 传入 Renderer。
- 远程与移动设备读取需要限制并发，避免压垮连接或设备。
- 图片像素差异优先使用 Worker/可中断任务；切换标签页时不阻塞主 UI。

### 14.2 可靠性

- 快速比较必须显示比较依据，避免把元数据一致宣传为内容一致。
- 目录读取错误必须进入结果模型，不能被 `.catch(() => [])` 转成空目录。
- 文件操作复用现有任务队列，移动/删除不作为 P0 对比操作。
- 比较结束后，左右源对象不因查看行为而被修改。

### 14.3 安全与隐私

- 文件内容只在本地应用进程中处理，不上传到网络服务。
- 路径、文件名、图片和文本内容不新增遥测。
- 覆盖、批量复制等高影响动作遵循现有确认与冲突策略。

### 14.4 可访问性

- 状态不能只依赖红/绿颜色，必须提供图标、文字和 Tooltip。
- 所有工具栏按钮具备可见焦点、辅助文本和快捷键提示。
- 差异导航可全键盘完成。
- 文本 Diff 保持 Monaco 自带辅助功能能力。

### 14.5 兼容性

- 本期主平台为 macOS。
- 主题使用现有 CSS 变量，支持深色和浅色模式。
- Renderer 不直接访问 Node API；新增文件读取/内容验证能力通过 `window.fileman` IPC 契约提供。
- IPC 变更需同步 `electron/main.ts`、`electron/preload.ts`、`src/env.d.ts`。

## 16. P0 验收标准

### 16.1 入口与路由

1. 同一面板选中两个目录，执行“对比”，打开文件夹对比标签。
2. 同一面板选中两个文本文件，执行“对比”，直接打开文本 Diff。
3. 同一面板选中两张图片，执行“对比”，直接打开图片对比。
4. 双面板左右各选一个同类对象时，可发起对比，左右关系与面板一致。
5. 选择目录与文件时，“对比”不可执行并说明原因。
6. 不同设备的两个可读对象可以发起对比。

### 16.2 文件夹比较

1. 同名条目按相对路径横向对齐，仅一侧存在时另一侧留空。
2. 快速比较将大小和时间均相同的文件标为“元数据相同，内容未验证”。
3. 对选中文件执行内容验证后，状态能更新为“内容相同”或“内容不同”。
4. 子目录未扫描时不显示为已确认相同。
5. 目录读取失败显示失败条目，不被误判为空目录或相同。
6. 过滤器生效后状态栏显示隐藏数量，一键可恢复全部。
7. 双击成对文本或图片打开对应子比较。
8. 复制到另一侧前能看见方向、数量和覆盖冲突；完成后状态自动刷新。

### 16.3 文本比较

1. 两侧文本正确加载并显示行级和行内差异。
2. `F7` 与 `Shift+F7` 可循环导航差异块。
3. 并排/内联、自动换行、空白显示和尾随空白规则切换即时生效。
4. P0 中用户无法误编辑或保存任一侧文本。
5. 从父目录进入时，可跳转到上一/下一组成对差异文本，并返回父会话原位置。

### 16.4 图片比较

1. 并排、滑动、叠加和差异模式均能正确显示同一对图片。
2. 并排模式两侧缩放和平移保持同步。
3. 图片不因尺寸不同被拉伸；额外区域在差异模式中计为差异。
4. 容差从 0–255 调整时，差异图和差异比例同步更新。
5. 透明区域使用棋盘格显示。
6. 大图或解码失败时显示原因，不崩溃、不显示错误的相同结论。
7. 从父目录进入时，可跳转到上一/下一组差异图片。

### 16.5 稳定性与安全

1. 远程或移动设备断连后，当前结果保留并提示连接失效。
2. 内容验证可取消，取消后不产生错误“相同”状态。
3. 比较期间文件变化时显示结果失效并要求重新加载。
4. 覆盖复制失败时源文件保持不变。
5. 深色与浅色主题下，所有状态文字和差异高亮均可辨识。

## 17. 建议数据模型调整

以下为产品语义要求，具体技术设计另行评审：

```typescript
type CompareKind = 'directory' | 'text' | 'image' | 'metadata'

type CompareStatus =
  | 'content-equal'
  | 'metadata-equal'
  | 'different'
  | 'left-newer'
  | 'right-newer'
  | 'left-only'
  | 'right-only'
  | 'type-mismatch'
  | 'pending'
  | 'comparing'
  | 'error'

type VerificationState =
  | 'not-requested'
  | 'pending'
  | 'running'
  | 'verified'
  | 'cancelled'
  | 'failed'

interface CompareSource {
  deviceId: string
  path: string
  file?: FileInfo
}

interface CompareSessionBase {
  id: string
  kind: CompareKind
  left: CompareSource
  right: CompareSource
  parentCompareSessionId?: string
  parentRelativePath?: string
  createdAt: number
}

interface CompareEntry {
  relativePath: string
  status: CompareStatus
  verification: VerificationState
  comparisonBasis: 'metadata' | 'content'
  left?: FileInfo
  right?: FileInfo
  error?: {
    side?: 'left' | 'right' | 'both'
    code: string
    message: string
  }
}
```

重点要求：

- 左右来源必须分别携带 `deviceId`，不得默认使用同一设备。
- “元数据相同”和“内容相同”必须是不同状态。
- 错误必须进入数据模型，不得通过空数组或空内容吞掉。
- 子比较必须能引用父会话和相对路径。

- 当前文件读取通过 Base64 整体返回，不适合大文件内容验证。

上述缺口由技术方案解决，PRD 不指定 IPC 名称、哈希算法或 Worker 实现。

## 19. 风险与未决决策

### 19.1 已采用的默认决策

- P0 文本对比只读，整文件复制可用，差异块级合并放到 P1。
- P0 不提供删除、镜像和自动双向同步。
- 文件夹默认快速比较，不把元数据一致称为内容一致。
- 任意两个可读来源均属于目标范围，包含跨设备比较。
- 对比会话 P0 不跨应用重启持久化。
- 图片视觉差异与 EXIF 元数据差异分开处理。

### 19.2 风险

| 风险 | 影响 | 缓解策略 |
|---|---|---|
| 远程/移动设备目录扫描慢 | 首屏等待、设备压力 | 懒加载、并发限制、渐进结果、取消 |
| 内容验证读取大量数据 | 带宽和耗时高 | 选中项优先、明确进度、P1 再支持全量验证 |
| 不同文件系统时间精度不同 | 误报较新/较旧 | 2 秒容差并展示比较依据 |
| Unicode/大小写规则不同 | 文件错误配对 | 名称正规化、冲突显式化、不自动猜测 |
| 图片 Diff 占用主线程 | UI 卡顿 | 限制解码尺寸、异步计算、可取消 |
| 过滤后批量操作范围不透明 | 误复制或遗漏 | 操作只作用于显式选择，显示隐藏数量和影响摘要 |
| 文件在比较中变化 | 结果过期 | 记录源元数据并在操作前复核，提示重新加载 |

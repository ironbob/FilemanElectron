# 文本预览日志排查能力（表达式过滤 + 着色方案）功能需求文档

> 日期：2026-08-15 ｜ 状态：待确认
> 产出模式：clarify-requirements（Full）

## 1. 一句话目标

为使用 FilemanElectron 排查日志的开发者，在文本文件预览中提供基于表达式的行级内容过滤和可自定义、可切换的着色方案，使其在大型日志文件中快速完成"缩小范围 → 定位关键行 → 看清上下文"的排障闭环。

## 2. 背景与成功标准

- 当前问题：文本预览（Monaco 只读视图）只能通读或依赖编辑器自带查找，无法按日志级别/关键词组合筛选，也无日志着色，排查大日志文件效率低，开发者被迫把文件拷到专业日志工具里看。
- 成功标准：开发者不离开本应用，即可对本地及远程设备上的日志文件完成"输入表达式过滤 → 命中计数确认范围 → 上下文定位问题 → 着色区分级别 → 导出证据"的完整排障流程。
- 产品阶段：既有能力改造（在现有文本预览上增强）。
- 建议模式：Lite——单角色（开发者本人）、单主流程、本地工具无合规风险。
- 用户最终选择：Full——用户于 2026-08-15 澄清开始时明确选择 Full，共回答 9 个澄清问题。

## 3. 用户与角色

| 角色 | 关键特征 / 目标 | 可以做 | 明确不能做 |
|---|---|---|---|
| 开发者（日志排查者） | 熟悉正则与布尔逻辑，排查本地/远程设备日志，对卡顿零容忍 | 使用表达式过滤、管理着色方案与规则、导出/导入方案、收藏过滤表达式、复制/导出过滤结果 | 修改被预览的源日志文件（预览全程只读） |

- **不是**目标用户：非开发型的普通文本阅读者（着色方案与表达式对其无意义，现有预览能力对其不变）。

## 4. 核心场景

- 场景 1（主流程）：开发者打开一个上百 MB 的服务日志 → 输入 `co(exception) and not co(timeout)` → 视图只保留匹配行（带原始行号）→ 命中计数显示 N 行 → 展开某命中行的前后上下文确认故障链路 → 导出这些行为新文件作为问题证据。
- 场景 2（级别筛查）：打开日志后套用"日志级别"内置着色方案，ERROR/WARN/INFO 行即刻分色；发现某类错误集中，再用 `level(error)` 过滤集中查看。
- 场景 3（段落定位）：只知道问题大概在文件后半段，用行号范围谓词先框定区间，再在该区间内做关键词过滤。
- 场景 4（团队共享）：团队成员各自调好一套针对本公司日志格式的着色方案，通过导出/导入文件共享，新成员开箱即用。
- 场景 5（远程排障）：通过 SMB/SSH/Android/iOS 设备浏览时直接预览远端日志，过滤与着色能力与本地一致。

## 5. 业务对象与术语

| 术语 / 对象 | 业务定义 | 与其他对象的关系 |
|---|---|---|
| 过滤表达式 | 用现有 textFilter 语法（`co/eq/word/reg` + `and/or/not`，大小写语义见 `src/components/filter/SYNTAX.md`）加上新增日志谓词组合成的行级筛选条件 | 表达式决定哪些行被保留；与着色方案相互独立 |
| 日志谓词（新增） | `level(x)` 按日志级别匹配、行号范围谓词按原始行号区间匹配，是对现有语法的增量 | 属于过滤表达式语法的一部分 |
| 匹配行 / 上下文行 | 匹配行：满足过滤表达式的行；上下文行：为帮助理解匹配行而附带显示的其前后相邻行，本身不满足表达式 | 上下文行依附于某个匹配行而显示，有明确的从属标记 |
| 着色规则 | 一条"匹配条件 + 颜色 + 作用范围（命中片段 / 整行）"的定义；匹配条件复用过滤表达式的叶谓词语法 | 多条规则有序组成一个着色方案 |
| 着色方案 | 一组有序的着色规则 + 一个方案名；分内置预设与用户自定义两类 | 全局唯一当前生效方案，作用于预览视图 |
| 内置预设方案 | 随应用提供的只读方案（如"日志级别着色"），不可被用户删除 | 可被复制为自定义方案后修改 |
| 自定义方案 | 用户创建/编辑/删除/复制的方案，持久保存 | 可导出为文件，亦可从文件导入为新方案 |
| 过滤历史 / 收藏 | 输入过的表达式自动留痕；标记为收藏的表达式可快速重用 | 全局维度的个人效率机制，不绑定具体文件 |
| 命中计数 | 当前过滤条件下匹配行的数量 | 随过滤条件实时更新 |
| 导出结果 | 将当前过滤视图中的行另存为一个新文本文件 | 只读预览的唯一"写出"出口，绝不写回源文件 |

## 6. 业务规则与状态

### 6.1 关键规则

- R1（只读铁律）：过滤、着色、导出全过程不得修改被预览的源文件；导出结果一律生成新文件。
- R2（行号保真）：过滤视图中显示的行号必须是原始文件行号；导出结果默认保留原始行号。
- R3（过滤与着色独立）：过滤表达式的变更不影响当前着色方案；切换方案不影响过滤条件；两者可任意组合。
- R4（上下文行从属）：上下文行仅作为匹配行的附带信息显示，有与匹配行可区分的视觉语义；同一行被多个匹配行同时作为上下文时只显示一次；反向过滤时，"命中"定义为不满足表达式的行，上下文围绕这些行展开。
- R5（规则优先级）：同一方案内着色规则有确定顺序；对同一行/同一片段，序号小（靠前）的规则先生效；整行着色与片段着色可叠加，但同一片段不叠加两种片段色。
- R6（方案切换即时生效）：切换着色方案后，当前视图（含已过滤状态）立即按新方案重新着色。
- R7（内置方案保护）：内置预设方案不可编辑、不可删除；用户对内置方案的个性化需求通过"复制为自定义方案"实现。
- R8（表达式容错）：表达式非法时不执行过滤、保持上一有效视图，并向用户指出错误位置/原因；表达式为空时视为不过滤，显示全文。
- R9（级别词表）：`level()` 识别的级别词（如 ERROR/FATAL/WARN/INFO/DEBUG/TRACE）在方案外独立配置，内置一份业界常见词表，用户可自定义补充；大小写不敏感。
- R10（持久化范围）：自定义着色方案、导入的方案、过滤历史与收藏全局持久保存；不按文件记忆过滤条件或方案（明确不做）。

### 6.2 生命周期 / 状态

| 对象 | 当前状态 | 触发事件 | 下一状态 | 谁可触发 | 不允许时的业务结果 |
|---|---|---|---|---|---|
| 着色方案（自定义） | 未启用 | 用户切换选择 | 生效中 | 开发者 | — |
| 着色方案（自定义） | 生效中 | 用户编辑规则 | 仍生效（即时按新规则着色） | 开发者 | — |
| 着色方案（内置） | 生效中 | 用户尝试编辑/删除 | 拒绝并保持原样 | — | 内置方案不可变更（R7） |
| 自定义方案 | 任意 | 用户删除 | 移除；若正生效则回退为"无着色" | 开发者 | — |
| 导入的方案 | 导入中 | 方案文件格式非法 | 导入失败并提示原因，不产生半成品方案 | 系统 | 既有方案不受影响 |
| 过滤条件 | 有效 | 用户修改为非法表达式 | 保留上一有效结果 + 错误提示 | 开发者 | 不清空当前视图 |
| 过滤条件 | 有效 | 用户清空 | 取消过滤，恢复全文 | 开发者 | — |

## 7. 功能清单

#### 模块 A：表达式内容过滤

| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0 | 行级表达式过滤 | 开发者在文本预览中输入 textFilter 语法表达式，视图只保留匹配行并显示原始行号与命中计数 | ① `co(error)` 过滤后仅显示含 error（不区分大小写）的行；② 行号与原文件一致；③ 命中计数与实际匹配行数相等 |
| P0 | 表达式容错 | 非法表达式不执行，提示错误原因与位置 | ① 输入 `co(error` 后视图保持上一有效状态且出现错误提示；② 清空表达式后恢复全文 |
| P0 | `level()` 级别谓词 | `level(error,warn)` 匹配级别为 error 或 warn 的行，大小写不敏感，级别词可自定义补充 | ① 对含 `ERROR`/`WARN` 级别词的日志行正确命中；② 用户新增自定义级别词后即可匹配 |
| P0 | 行号范围谓词 | 按原始行号区间限定过滤范围（语法示例 `lines(1000-2000)`，具体关键字在语法设计时定），可与其它谓词布尔组合 | ① 单独使用时仅显示区间内行；② 与 `co(x)` 组合时仅返回区间内且含 x 的行 |
| P1 | 上下文行 | 为命中行附带显示前后 N 行（N 可调，默认 3），上下文行有从属标记且可折叠 | ① 开启后命中行前后各显示 N 行；② 同一行不重复显示；③ 关闭后回到仅匹配行 |
| P1 | 反向（排除）过滤 | 一键反选：显示所有不满足表达式的行 | 对同一表达式，正向命中数 + 反向命中数 = 总行数 |
| P1 | 过滤历史与收藏 | 输入过的表达式自动进入历史；可收藏常用表达式，可快速重选与取消收藏 | ① 历史按时间倒序可重选；② 收藏项在重启应用后仍在 |

#### 模块 B：着色方案

| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0 | 片段/整行着色渲染 | 按生效方案的规则对视图着色：片段规则只着色命中子串，整行规则着色整行；叠加遵循 R5 | ① 片段规则仅命中子串变色；② 整行规则整行变色；③ 与过滤同时开启时各自独立生效 |
| P0 | 内置预设方案 | 提供开箱即用的"日志级别着色"等预设（至少 1 套，建议 2 套：级别着色、通用增强） | ① 打开日志无需配置即可切换预设；② 预设不可编辑/删除 |
| P0 | 自定义方案 CRUD | 用户可新建、编辑（增删改规则、调整顺序、改名）、复制、删除自定义方案，规则含匹配条件、颜色、作用范围三要素 | ① 新建方案含 ≥1 条规则即可生效；② 调整规则顺序后着色优先级随之变化；③ 删除生效中方案后回退为无着色 |
| P1 | 方案切换 | 一键切换当前生效方案，立即重新着色（R6） | 切换后无需重新打开文件即完成重新着色 |
| P1 | 方案导入导出 | 自定义方案可导出为文件；导入文件生成新的自定义方案，重名不覆盖既有方案 | ① 导出→导入同一方案后着色效果一致；② 导入非法文件时报错且不产生半成品 |

#### 模块 C：结果操作

| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P1 | 复制/导出过滤结果 | 可复制选中/全部过滤结果行，或将过滤结果导出为新文本文件；导出不改动源文件（R1、R2） | ① 复制内容含原始行号与行文本；② 导出生成的新文件行数 = 当前过滤视图行数 |
| P1 | 命中项导航 | 在过滤/着色命中项之间上一处/下一处跳转 | 跳转可在所有命中项间循环，且当前所处位置可知 |

## 8. 关键异常与失败结果

| 场景 | 异常 / 边界条件 | 期望业务结果 |
|---|---|---|
| 输入表达式 | 语法非法（未闭合括号、未知关键字、空值等） | 不执行过滤，保留上一有效视图，提示错误位置/原因（R8） |
| 输入表达式 | 正则谓词使用了引擎不支持的正则特性 | 视为非法表达式处理，提示具体不支持项 |
| 过滤结果 | 0 行命中 | 明确显示"0 命中"，保留全文视图可撤销，不显示空白 |
| 过滤结果 | 命中行数极大（如数十万行） | 视图可流畅滚动，不冻结界面（见性能约束） |
| 着色规则 | 规则的正则非法 | 该条规则不生效并标红提示，其余规则正常着色 |
| 着色规则 | 多规则颜色冲突 | 按 R5 确定顺序解析，结果可预期 |
| 方案导入 | 文件格式非法/版本不兼容 | 导入失败并说明原因，既有方案不受影响 |
| 方案删除 | 删除正生效的方案 | 立即回退为无着色，不残留错误着色 |
| 大文件 | 文件超过性能承诺上限（约 100MB） | 允许尽力而为，但需在超出时以可感知方式告知用户性能可能下降，不得静默卡死 |
| 远程文件 | 远程读取中断 | 沿用现有预览的错误处理，过滤/着色状态不产生脏数据 |

## 10. 外部依赖

- 现有 textFilter 表达式引擎（`src/utils/textFilter/`）——复用其语法与求值；新增谓词需在其语法框架内扩展。
- 现有 Monaco 文本预览组件（`PreviewTextContent.vue`）——着色与过滤渲染在其只读视图上叠加；需遵守项目 Monaco 接入规约（`疑难问题解决记录/monaco-editor-electron29-接入注意事项.md`）。
- 现有远程适配器体系——远程文件内容读取沿用现有 `readFile` 链路，本需求不改变适配器接口。

## 11. 明确不做（Out of scope）

- 不做时间范围/时间戳解析谓词：用户明确排除；需要时可基于现有 `reg()` 谓词近似表达时间模式。
- 不做 diff 视图（FileDiffView）的过滤/着色：用户明确排除，首版聚焦文本预览。
- 不做 tail -f / 文件变更实时跟随：文件管理器预览的是静态快照，实时监视是另一产品形态。
- 不做结构化日志（JSON 日志字段化、列视图、字段级过滤）：属重量级日志平台能力。
- 不做书签/行标记、按文件记忆过滤状态、按文件名自动套用方案：用户在澄清中未选，YAGNI。
- 不做"跳转原文位置"（从过滤行跳回全文视图对应位置）：用户在澄清中未选；上下文行已部分覆盖该诉求。
- 不做着色方案的在线分享/规则市场：导出/导入文件已满足团队共享。
- 不做过滤结果的统计分析（错误分布、时间分布图表）：超出排障闭环。

## 12. 假设、风险与未决问题

### 12.1 未验证假设

（Full 模式下仍需标注的推断性假设）

- 假设 1：上下文行默认 N=3、可调范围 1-10 可满足绝大多数排障场景——依据 grep -C 惯例；若不成立仅影响默认值设定，不影响范围。
- 假设 2：内置"日志级别"预设方案只需覆盖 ERROR/WARN/INFO/DEBUG/TRACE 常见五级 + 时间戳/线程片段着色——依据业界通用日志格式；若用户日志格式特殊，可复制为自定义方案调整。
- 假设 3：行号范围谓词的行号与视图显示的原始行号同源（R2），无需第二套行号概念——依据过滤视图行号保真规则。
- 假设 4：现有 textFilter 引擎的语法框架可无破坏性地扩展新谓词（不改动现有文件列表过滤的行为）——依据 SYNTAX.md 的分层设计；若不成立需评估语法扩展方案，属于技术设计阶段课题。

### 12.2 已知风险

- 性能风险：百 MB 级文件的正则逐行求值与着色叠加是主要性能压力点；已通过"防抖 + 秒级出结果"约束兜底，具体手段（增量计算/分块）属技术设计阶段。
- 主题冲突风险：自定义颜色在双主题下的可读性无法静态保证（用户可选取极端颜色）；已通过约束声明 + 无障碍条款缓解，不阻止用户选择。
- 复用风险：textFilter 引擎当前服务于文件列表过滤，扩展谓词若引入行为变化可能波及现有功能；假设 4 未验证前视为风险。

### 12.3 未决问题

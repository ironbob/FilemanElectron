# Git 状态徽标 + 命令面板（M2）功能需求文档

> 日期：2026-08-15 ｜ 状态：已确认（随「程序员工作台功能套件」总体规划批准）
> 产出模式：总体规划之 M2 套件（F3 只读 Git 徽标 + F4 命令面板）

## 1. 一句话目标

让开发者在文件列表里直接看到 git 修改/未跟踪状态与分支信息（无需开 IDE），并以 ⌘⇧P 命令面板键盘直达所有高频动作与目录跳转。

## 2. 背景与成功标准

- 当前问题：Finder 式列表对 git 仓库「全盲」——哪个文件改了、哪些是新文件、当前在哪个分支，一概不可见；功能入口散落在右键菜单/侧栏/快捷键，键盘用户要在多个界面间往返。
- 成功标准：① 打开本地仓库目录即见 M/U 等徽标与分支 chip，IDE 保存后数秒内徽标更新；② ⌘⇧P 输入两三个字即可执行任意内置动作或跳转收藏目录。

## 3. 用户与角色

| 角色 | 关键特征 / 目标 | 可以做 | 明确不能做 |
|---|---|---|---|
| 开发者 | 仓库中高频切换/浏览，键盘优先 | 查看徽标与分支、用命令面板执行动作/跳转 | stage/commit/push 等写操作（明确不做 git 客户端） |

## 4. 核心场景

- 场景 1（徽标）：打开仓库目录 → 修改过的文件旁橙色 M、未跟踪蓝色 U、冲突红 C；干净文件无徽标。
- 场景 2（分支）：面板工具栏路径区出现 `main ↑2` chip，悬停显示仓库根。
- 场景 3（面板）：⌘⇧P → 输「分栏」→ Enter → 当前面板切分栏视图；输入 `/Users/x` 直接跳转；输入收藏名跳收藏目录。

## 5. 业务对象与术语

| 术语 | 定义 | 关系 |
|---|---|---|
| GitDirectoryStatus | 一次的 git 快照（isRepo/repoRoot/branch/ahead/behind/entries） | 渲染层缓存键 = (deviceId, dirPath) |
| XY 状态字母 | porcelain v1 的暂存区(X)/工作区(Y) 列 | 徽标字母由此归并（冲突优先） |
| 徽标 kind | untracked/modified/added/deleted/renamed/conflict 六类 | CSS 变量配色，双主题可读 |
| 命令 | { id, title, group, shortcut?, keywords?, run(ctx) } | 注册表按 id 去重，面板消费 |
| 命令上下文 | 活动面板信息 + 导航回调 | 命令据此决定行为，面板不解释语义 |

## 6. 业务规则

- R1（只读铁律）：git 集成全程只读（status/rev-parse），绝不出现任何写仓库的操作。
- R2（本地限定）：仅 deviceId==='local' 查询；远程/ZIP 不查询不渲染。
- R3（负缓存）：非仓库目录主进程 30s 负缓存，导航风暴不产生 exec 风暴。
- R4（失效时机）：watch:changed 命中本目录或所在仓库范围 → 缓存失效重取。
- R5（徽标归并）：?? → U；冲突组合 → C；其余按 M/A/D/R 优先级取首见字母；`!`（忽略）不显示。
- R6（命令注册生命周期）：功能组件挂载注册/卸载注销；面板只消费注册表，不知道具体命令。
- R7（键盘消费契约）：面板内 ↑↓/Enter/Esc 由面板捕获期消费（LIFO），不得落入 FileList 冒泡监听。
- R8（手输路径）：以 `/` 开头的查询视为目录跳转候选（置顶），Enter 导航当前面板。

## 7. 功能清单

#### 模块 A：Git 徽标（F3）

| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0 | 状态徽标 | 仓库目录内 list/grid/columns 三视图名称旁徽标 | 修改/未跟踪/干净文件三类渲染正确（e2e） |
| P0 | 分支 chip | 工具栏路径区分支名 + ahead/behind 箭头 | `main ↑2` 形态 + title 显示仓库根 |
| P0 | 非仓库零开销 | isRepo:false 时无徽标无 chip，不重复 exec | 30s 负缓存（R3） |
| P1 | watch 联动 | 目录变化后徽标集合刷新 | watch 事件后新状态生效（e2e） |

#### 模块 B：命令面板（F4）

| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0 | ⌘⇧P 呼出 | 捕获期快捷键，面板与输入自动聚焦；Esc 关闭 | 呼出/关闭/再呼出（e2e） |
| P0 | 模糊过滤执行 | 子序列评分（前缀/词首/连续加权），Enter 执行 | 「分栏」→ 分栏视图生效（e2e） |
| P0 | 手输路径跳转 | `/` 开头查询置顶为「前往」候选 | Enter 后当前面板导航（e2e） |
| P1 | 收藏跳转 | 收藏目录动态并入候选 | 输入收藏名 → 跳转（e2e） |
| P1 | 内置命令集 | 标签页/视图/外观/刷新 10 项内置 | 注册表可扩展（M3/M4 挂载注册） |

## 8. 关键异常

| 场景 | 期望结果 |
|---|---|
| git 未安装 / 超时(5s) | 按非仓库处理（负缓存），无报错弹窗 |
| index.lock 竞争导致 status 失败 | isRepo:true + 空 entries，不长时间负缓存 |
| 仓库根无法解析（rev-parse 失败） | 非仓库路径 |
| 面板打开时活动标签是工具视图 | activePane 为空，命令自行降级（视图类命令 no-op） |

## 9. 约束

- 徽标渲染不得改变行高/key-field/RecycleScroller 结构（RISK-04 红线）。
- 颜色仅用 CSS 变量（--accent-*）。
- git 经 execFile 参数数组（无 shell 层）；porcelain 路径相对仓库根（实测），必须 rev-parse 拿 repoRoot 转绝对路径。

## 10. 明确不做

- 不做 stage/commit/branch 等 git 写操作（与 Fork/Tower 重复）。
- 不做 git log/blame 视图。
- 不做面板的命令参数输入（后续需要时再评估）。

## 11. 假设与风险

- 假设：`git status --porcelain=v1 -z --branch` 跨 git 版本稳定（porcelain 承诺）。
- 假设：5s 超时覆盖绝大多数仓库（Linux 内核级仓库可能超时 → 空徽标可接受）。
- 风险：超大仓库 status 耗时（数秒）阻塞感 —— 徽标为旁路装饰，慢只表现为迟到不阻塞 UI；必要时后续加防抖合并。

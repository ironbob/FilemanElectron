# 目录监听自动刷新 + 路径快赢（复制路径变体 / 打开方式）功能需求文档

> 日期：2026-08-15 ｜ 状态：已确认（随「程序员工作台功能套件」总体规划批准）
> 产出模式：总体规划（12 功能 5 里程碑）之 M1；本文档为 M1 套件（F2 目录监听 + F5 路径快赢 + 共享基建）的业务需求记录

## 1. 一句话目标

让双面板文件管理器在目录被外部程序（构建、日志、同步工具）改变时自动呈现最新内容而不打扰用户的选区与滚动，并为开发者提供一键复制多种形态路径、用常用开发工具（VS Code/iTerm2 等）直接打开的能力。

## 2. 背景与成功标准

- 当前问题：`fs:list` 是纯拉模式，目录变化只能手动 ⌘R 刷新；盯构建输出、等编译产物、看日志目录增长时体验割裂。复制路径只有手抄或经系统 Finder 中转；「用 VS Code 打开当前目录」要先开 Finder 再拖拽。
- 成功标准：① 在 IDE 里保存文件后 ~1s 内文件管理器列表自动更新，选区不丢；② 右键两步内把 POSIX 路径 / file:// URI / 相对另一面板路径放进剪贴板；③ 检测到 VS Code 等工具后右键一步打开。
- 产品阶段：既有能力增强（M1 同时铺设 M3/M4 复用的共享基建：SessionTaskRegistry / DirectoryWalker / fileHashing / useLongTaskProgress / 瞬态工具页模式）。

## 3. 用户与角色

| 角色 | 关键特征 / 目标 | 可以做 | 明确不能做 |
|---|---|---|---|
| 开发者（主用户） | 双面板高频使用者，常与终端/IDE 并排工作 | 享受自动刷新、关闭自动刷新、复制各形态路径、用已装开发工具打开本地条目 | 修改被监听目录的内容（监听是只读旁路） |

- **不是**目标用户：需要实时 tail -f 内容跟随的运维（那是预览/日志工具的形态，见「明确不做」）。

## 4. 核心场景

- 场景 1（本地自动刷新）：开发者在右面板开着 `dist/`，IDE 构建产出新文件 → 列表 ~1s 内出现新条目，原选中项保持选中。
- 场景 2（远程轮询刷新）：左面板挂着 SMB/SSH 目录，远端被同事写入 → 数秒内列表更新；应用失焦时暂停轮询，不做无谓流量。
- 场景 3（复制路径写配置）：双面板左 `/etc/nginx` 右 `/usr/local/etc`，右键右面板文件 →「复制路径 ▸ 相对另一面板」得到 `../../../etc/nginx/nginx.conf`，直接粘进脚本。
- 场景 4（打开方式）：右键项目目录 →「打开方式 ▸ VS Code」直接以该目录打开编辑器。

## 5. 业务对象与术语

| 术语 / 对象 | 业务定义 | 与其他对象的关系 |
|---|---|---|
| 目录订阅 | 「某设备某目录需要变化通知」的登记，引用计数（双面板/多标签同目录只一份底层资源） | 订阅存在才有推送；FileList 挂载周期与展示对齐 |
| 变化推送（watch:changed） | 主进程发出的「该目录可能变了」信号，**不携带变化明细** | 渲染层收到后自行 diff 决定是否刷新 |
| diff 守卫 | 渲染层用「名字+大小+修改时间」签名比对新旧列表，无差异则不刷新 | 保护选区/滚动，是推送与刷新之间的闸门 |
| 路径变体 | POSIX 绝对路径 / file:// URI / 相对另一面板的相对路径 / 纯文件名 | 复制动作的四种产物；同一右键入口 |
| 打开方式 | 用本机已安装的开发者应用（.app 包）打开本地文件/目录 | 仅本地设备与非 ZIP 路径可用 |
| 本地引擎 | `fs.watch` 非递归监听（macOS FSEvents），事件按目录 300ms 合并 | 与远程引擎并列，调用方无感 |
| 远程引擎 | 周期 `list` 快照 diff（3.5s），首个远程订阅才启动轮询循环 | SSH SFTP 无推送通道，轮询是唯一途径 |

## 6. 业务规则与状态

### 6.1 关键规则

- R1（只读旁路）：监听不修改任何被监听目录的内容；订阅/退订是唯一状态变更。
- R2（选区保护）：变化推送不得直接触发整页重载——必须先 diff，签名无变化不刷新；有变化才重载。
- R3（资源即释）：最后一个订阅者退订即释放底层 watcher/停止轮询；本地 watcher 出错（目录被删/卷弹出）自动放弃订阅，不重试风暴。
- R4（远程节流）：远程轮询单请求在途、应用失焦跳过；连续失败达上限放弃订阅（静默退化为手动刷新），设备重连后重新订阅即可恢复。
- R5（ZIP 除外）：ZIP 虚拟路径（`::` 协议）不支持监听——无对应实体目录。
- R6（复制只读）：复制路径任何变体只读不写；相对路径为纯词法计算，不解析符号链接、不触碰文件系统。
- R7（打开方式本地限定）：open-with 仅对本地设备、非 ZIP 路径可见；应用探测结果缓存，探测失败仅隐藏菜单项不报错。
- R8（默认开启可关）：自动刷新默认开启；用户可在设置中关闭（关闭后仍可 ⌘R 手动刷新）。

### 6.2 生命周期 / 状态

| 对象 | 当前状态 | 触发事件 | 下一状态 | 谁可触发 | 不允许时的业务结果 |
|---|---|---|---|---|---|
| 目录订阅 | 无订阅 | FileList 挂载/路径切换 | 已订阅（计数 1..n） | 系统 | — |
| 目录订阅 | 已订阅 | 最后一个退订 | 无订阅（释放 watcher/停轮询） | 系统 | — |
| 本地 watcher | 监听中 | 目录删除/卷弹出 | 放弃订阅（一次终态推送） | 系统 | 不重试、不报错弹窗 |
| 远程轮询 | 轮询中 | 连续失败 ≥10 次 | 放弃订阅 | 系统 | 静默退化，重订即恢复 |
| 推送事件 | 到达渲染层 | diff 签名无变化 | 忽略（不刷新） | 系统 | 选区/滚动原样 |
| 推送事件 | 到达渲染层 | diff 签名有变化 | 重载列表（loadFiles） | 系统 | — |

## 7. 功能清单

#### 模块 A：目录监听自动刷新（F2）

| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0 | 订阅与推送 | FileList 挂载即订阅当前 (deviceId, path)，卸载/切换即退订；主进程经 `watch:changed` 推送 | ① 列表出现即建立订阅；② 切换目录后旧目录不再收到刷新；③ 同目录双面板只占用一份底层资源 |
| P0 | 本地自动刷新 | 目录条目变化（新建/删除/改名/大小/mtime 变化）后 ≤1s 列表更新 | 外部 `touch`/新建文件后 1s 内新条目可见 |
| P0 | diff 守卫（选区保护） | 无实质变化的推送不刷新 | 无变化事件后选中项与滚动位置不变（R2） |
| P1 | 远程轮询刷新 | SMB/SSH/WebDAV/Android 目录周期快照 diff，变化即推送；失焦暂停；失败上限放弃（R4） | 远端新建文件后 ≤2 个轮询周期内出现；失焦期间不发请求 |
| P1 | 设置开关 | `autoRefresh` 设置（默认 true），关闭后忽略推送 | 关闭后外部变化不触发刷新，⌘R 仍可用 |
| P1 | 事件合并 | 本地事件风暴（如构建写百个文件）按目录 300ms 合并为一次推送 | 风暴期间列表不闪烁抖动 |

#### 模块 B：复制路径变体（F5a）

| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0 | POSIX 路径 / file:// URI / 文件名 | 右键「复制路径 ▸」子菜单三变体；多选时按行拼接 | ① 剪贴板得到正确绝对路径；② 含空格路径的 URI 正确转义；③ 多选得到多行 |
| P0 | 相对另一面板 | 同设备存在另一面板时提供；词法计算 `..` 上行 | `/alpha` 面板对 `/alpha/x.txt` 在 `/beta` 面板视角得到正确相对路径 |

#### 模块 C：打开方式（F5b）

| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P1 | 开发者应用打开 | 探测 /Applications 与 ~/Applications 下常见工具（VS Code/Cursor/iTerm2/Sublime/Zed/Xcode 等），右键「打开方式 ▸」 | ① 装有 VS Code 的机器一步打开；② 未装任何候选时菜单项隐藏 |

## 8. 关键异常与失败结果

| 场景 | 异常 / 边界条件 | 期望业务结果 |
|---|---|---|
| 本地监听 | 被监听目录被删除/所在卷弹出 | watcher 报错 → 自动放弃订阅，退化为手动刷新，无报错弹窗（R3） |
| 远程轮询 | 设备断连 | 轮询跳过（不计数失败），重连后自动续上基线 |
| 远程轮询 | 连续失败 ≥10 | 放弃该订阅并日志记录；用户重新进入目录自然重订（R4） |
| 订阅时机 | 目录在订阅前已被删除 | 订阅失败仅记录，列表加载本身不受影响 |
| 推送风暴 | 构建脚本短时间写大量文件 | 300ms 窗口合并为单次推送 + diff 守卫拦截无变化刷新 |
| 复制路径 | 剪贴板被占用/权限异常 | 沿用现有 copyToClipboard 的 textarea 回退 |
| 打开方式 | 应用探测失败 / open 失败 | 菜单项隐藏 / console 记录错误，不打断界面 |
| ZIP 虚拟路径 | 在 ZIP 内部目录浏览 | 不订阅、不出现宿主集成菜单（R5/R7） |

## 9. 非功能与领域约束

| 类别 | 约束 / 要求 | 状态 | 依据 / 风险 |
|---|---|---|---|
| 性能 | 本地变化到刷新 ≤1s；diff 守卫避免无变化整页重载 | 已确认 | 盯构建产物场景 |
| 资源 | 不新增 npm 依赖实现监听（fs.watch 原生递归能力不用，选非递归精确事件）；轮询循环无订阅即停 | 已确认 | 项目零依赖倾向 |
| 兼容 | 远程轮询对 SMB/SSH 友好（单请求在途、顺序遍历） | 已确认 | 既有 DirectoryStatsService 同款约束 |
| 安全 | open-with 用 execFile 参数数组不经 shell | 已确认 | HostShellService 既有「无引号地狱」原则 |
| 作用范围 | 自动刷新覆盖本地+远程；open-with 仅本地 | 已确认 | 远程无宿主 .app 语义 |

- M1 共享基建（本套件顺带落地，供 M3/M4 复用）：`SessionTaskRegistry`、`DirectoryWalker`、`fileHashing`（由 ContentVerificationService.hashFile 泛化）、`ToolPathResolver.resolveTool` 泛化、`useLongTaskProgress`、`tabs.isTransientTab`、`shellQuote` 提取。

## 11. 明确不做（Out of scope）

- 不做 tail -f / 文件内容级实时跟随：列表级自动刷新与内容级跟随是两种产品形态。
- 不做远程推送（SMB change notify / SSH inotify 转发）：轮询已满足；推送属优化。
- 不做递归子树监听：面板一次只展示一层，深层变化不影响该层列表（非递归 fs.watch 语义精确匹配需求）。
- 不做「打开方式」全量应用枚举（LaunchServices 全扫描）：仅探测开发者常用工具白名单。
- 不做 chokidar 依赖引入：原生 fs.watch + 自实现合并已满足。

## 12. 假设、风险与未决问题

- 假设 1：3.5s 远程轮询周期在「及时感」与「设备负载」间可接受——VolumeScanner 4s 先例量级；不成立则调周期即可。
- 假设 2：fs.watch 非递归在 macOS 上对挂载卷（/Volumes/*）工作正常；FSEvents 对网络卷可能延迟——远程卷本来就走本地路径监听，若异常退化为手动刷新可接受。
- 假设 3：macOS `open -a <bundlePath> <target>` 对所有候选 .app 语义一致（bundle 内 CFBundleDocumentTypes 决定接收行为）——Xcode 等对无关联文件类型可能只打开应用不定位文件，属可接受降级。
- 风险：fs.watch 事件风暴在极端场景（万级文件瞬时写入）下合并窗口后仍触发多次 diff 拉取——diff 守卫 + 300ms 合并已缓解，必要时后续加指数退避。
- 未决：远程轮询周期是否需要按设备类型区分（SSH 可更激进、SMB 更保守）——留待 M3 设备感知增强时统一评估。

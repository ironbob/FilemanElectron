# 移动设备文件管理(Android / iOS)功能需求文档

> 本文档为 FilemanElectron 补齐 Android(ADB)与 iOS(libimobiledevice)文件管理能力的**功能需求**。
> 仅描述用户、业务行为、范围、约束、风险与验收;不涉及 UI 布局、技术架构、数据模型或 API 设计。
> 日期:2026-08-07。

---

### 1. 一句话目标

为【自用的高级用户/开发者】,在【通过 USB 把手机连到 Mac、想在双面板文件管理器里像管理本地文件一样管理手机文件】的场景下,解决【当前手机文件操作层(AndroidAdapter/iOSAdapter)失效、无法真正浏览/传输/增删改手机文件】的问题,产出【Android 与 iOS 两平台可用的手机文件管理能力】。

### 2. 背景与成功标准

- **当前问题**:设备发现层(`MobileDeviceScanner`,通过 `adb devices` / `idevice_id` 等 CLI)已实现且可用,但文件操作层失效:
  - Android:依赖未安装的 `adbkit`;且 `device.shell()` 返回流被当字符串处理;`stat()`/时间戳为桩代码(全 0/假值)。
  - iOS:全部文件操作依赖一个**并不存在**的 `idevicefs` CLI;且无真正的 `idevicepair pair` 配对发起流程。
  - 后果:能"看到"手机出现在侧栏,但点进去无法浏览、无法传输,形同未实现。
- **成功标准**:
  1. Android(开了 USB 调试)连接后,可在双面板中浏览 `/sdcard` 用户存储、读取/写入/新建/重命名/删除/搜索文件,并与本地、SMB/SSH 远程双向复制/移动。
  2. iOS 连接并完成"信任此电脑"配对后,可在 AFC 沙盒边界内浏览、读取、受控写入/删除,并与本地、SMB/SSH 远程双向复制/移动;AFC 不支持的操作给出明确报错而非静默失败。
  3. 所需的 `adb` / `libimobiledevice` 工具随应用分发(打包进安装包),用户无需自行安装。
  4. 传输有进度、可取消、取消或失败不残留半成品文件。
- **产品阶段**:既有能力改造(在已搭好的设备发现 + 双面板 + 跨设备传输骨架上,补齐失效的手机文件操作层)。
- **建议模式**:Full —— 范围决策(可访问区域、读写口径、配对流程、跨设备方向、工具打包)会级联影响能力/异常/验收,且存在平台特有风险(iOS 沙盒、Android 解析脆弱、写入致损、LGPL 打包合规)。
- **用户最终选择**:Full(用户在模式选择时确认采用 Full,2026-08-07)。

### 3. 用户与角色

| 角色 | 关键特征 / 目标 | 可以做 | 明确不能做 |
|---|---|---|---|
| 使用者(高级用户/开发者,单用户) | 能自行处理 USB 调试、信任授权;能看懂报错;在 Mac 上管理连入的手机文件 | 浏览/传输/增删改手机用户区文件;跨设备复制移动;同时连多台手机、批量操作;应用内预览手机文件 | 访问 Android root/系统区;访问 iOS 越狱全文件系统;无线/网络传输;双向目录同步 |

- **不是**目标用户:需要向导式引导的纯普通用户、需要多成员权限/审计的企业团队场景。

### 4. 核心场景

- 场景 1(Android 传输):用户把开了 USB 调试的 Android 手机连上 Mac → 侧栏出现设备 → 双击进入浏览 `/sdcard` → 把一批照片/视频从手机**移动**到本地或 SMB/SSH 远程 → 传输有进度,可中途取消且不留残文件。
- 场景 2(iOS 配对后管理):用户连上 iPhone → 侧栏出现设备并标注"待配对" → 在应用内发起配对 → 手机弹"信任此电脑"、用户点信任并输密码 → 状态变为"已配对/可浏览" → 浏览 AFC 沙盒(照片等)、导出到本地;尝试在不支持的区域(如 DCIM 内建目录)操作时收到明确报错。
- 场景 3(未授权 Android 引导):连上 Android 但侧栏显示"待授权"(USB 调试未放行)→ 应用引导用户在手机上点"允许"→ 状态恢复后自动可浏览,无需重连。
- 场景 4(跨远程搬运):手机某文件需落到 SMB/SSH 远程 → 在双面板中直接从手机面板复制/移动到远程面板。
- 场景 5(中途状态变化):连接过程中用户拔线或在手机上撤回信任 → 运行时检测到 → 当前操作以明确原因失败,设备状态降级,不产生静默脏数据。

### 5. 业务对象与术语

| 术语 / 对象 | 业务定义 | 与其他对象的关系 |
|---|---|---|
| 移动设备 | 一台通过 USB 连入的 Android 或 iOS 手机,有唯一标识(Android 序列号 / iOS UDID)、名称、型号、平台类型 | 拥有一个连接状态、(iOS)一个配对状态 |
| 连接状态 | 设备相对于"可被文件操作访问"的状态:未检测 / 已检测-待授权(Android)或待配对(iOS) / 已就绪(可浏览) / 已断开 | 由发现层轮询与运行时校验共同维护 |
| 配对关系(iOS) | 该 iOS 设备与本机之间经"信任此电脑"建立的信任;AFC 访问的前置条件 | 可被发起、校验、失效(撤回/过期)后需重新建立 |
| 手机文件 | 手机可访问区域(Android `/sdcard` 用户存储 / iOS AFC 沙盒)内的文件与目录 | 可被浏览、读取、写入、改名、删除、跨设备复制/移动 |
| 跨设备传输任务 | 在手机与本地/SMB/SSH 之间复制或移动一个或多个文件/目录的单位 | 走传输队列;有进度、可取消;移动 = 复制成功后删源 |
| 工具运行时 | 随应用分发的 `adb` 与 `libimobiledevice` 工具集 | 设备发现与文件操作都依赖其可用 |

### 6. 业务规则与状态

#### 6.1 关键规则
- **R1(访问前置)**:任何手机文件操作都必须在设备处于"已就绪(可浏览)"状态时进行;否则操作被拒绝,并给出具体原因(待授权 / 待配对 / 离线 / 工具不可用)。
- **R2(iOS 配对前置 + 运行时校验)**:iOS 文件操作前必须存在**有效**配对;不仅连接时校验,长连接期间也需校验;配对失效(撤回/过期)时降级为"待配对"并提示重新配对,**不得静默失败**。
- **R3(能力边界,拒绝静默)**:仅在 AFC 沙盒 / Android 用户存储的能力边界内执行操作;因沙盒/系统限制导致的不支持操作(典型如 iOS DCIM 区建目录/改名)必须返回**明确**错误,不得静默、不得部分执行后假装成功。
- **R4(传输语义)**:跨设备复制/移动走队列;移动 = 复制成功后删除源;传输可取消;取消或失败必须清理目标端半成品临时文件,不在设备上残留。
- **R5(删源安全)**:移动操作只有在目标端写入校验通过后才删除源;复制/传输失败时**绝不**删除源。
- **R6(元数据真实)**:文件列表/属性需返回真实的大小与修改时间等元数据,**不得返回桩数据**(纠正现有 `stat()` 全 0 / 时间戳不解析的问题)。
- **R7(覆盖冲突)**:目标已存在同名文件时,按"询问覆盖/跳过/重命名"处理(沿用现有文件操作覆盖语义);不允许默认静默覆盖。

#### 6.2 生命周期 / 状态

**移动设备连接状态**(Android 与 iOS 共用主状态;iOS 额外叠加配对子状态):

| 对象 | 当前状态 | 触发事件 | 下一状态 | 谁可触发 | 不允许时的业务结果 |
|---|---|---|---|---|---|
| 移动设备 | 未检测 | USB 连入并被工具识别 | 已检测(待授权/待配对) | 系统(用户插线) | 工具不可用时不进入此状态,显示平台禁用 |
| 移动设备(Android) | 已检测-待授权 | 用户在手机上点"允许 USB 调试" | 已就绪(可浏览) | 使用者(在手机操作) | 仍为待授权时,浏览/操作被拒并提示去授权 |
| 移动设备(iOS) | 已检测-待配对 | 在应用内发起配对且手机端信任 | 已就绪(可浏览) | 使用者(应用发起 + 手机确认) | 配对被拒/失败时停留在待配对,可重试 |
| 移动设备 | 已就绪(可浏览) | 拔线 / 撤回信任 / 授权被取消 | 已断开(或降级回待授权/待配对) | 系统/使用者 | 进行中的操作以明确原因失败,不留残文件 |
| 移动设备 | 已就绪 | 用户主动断开 | 已断开 | 使用者 | 清理该设备连接 |

**iOS 配对子状态**:

| 当前状态 | 触发事件 | 下一状态 | 不允许时的业务结果 |
|---|---|---|---|
| 未配对 | 应用发起配对 | 配对中 | 工具不可用时报错 |
| 配对中 | 手机端"信任此电脑"+输密码成功 | 已配对 | 用户拒绝/超时 → 回未配对,可重试 |
| 已配对 | 校验发现失效(撤回/过期) | 未配对(提示重新配对) | 不静默降级,显式提示 |

> Android 的"USB 调试授权"由手机端弹窗决定,应用不发起、只检测与引导;故不单列发起态。

### 7. 功能清单

> 优先级:P0=该阶段上线最小闭环必需;P1=显著影响核心结果;P2=可延后。
> 阶段标注:**阶段1=Android**;**阶段2=iOS**(用户已确认分阶段交付,Android 先行)。

#### 模块:设备连接与状态(两平台共用)
| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0(阶段1) | Android 设备发现与授权引导 | 发现已连入的 Android 设备;识别授权状态;未授权时在侧栏标注并引导用户在手机上允许 USB 调试;授权恢复后自动转为可浏览 | 已授权设备可进入浏览;未授权设备有明确"待授权"标识与引导;授权前后状态能自动更新 |
| P0(阶段2) | iOS 设备发现与配对生命周期 | 发现已连入的 iOS 设备;支持在应用内发起配对;校验配对有效性;失效时提示重新配对 | 首次发起配对能触发手机"信任此电脑";信任成功后可浏览;配对失效后被识别并提示重配,不静默失败 |
| P0(两阶段) | 工具随应用分发 | 所需的 `adb`(阶段1)/ `libimobiledevice`(阶段2)随应用打包,安装即可用 | 全新机器安装应用后,无需用户另行安装命令行工具即可发现并连接对应平台设备 |

#### 模块:文件浏览与元数据
| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0(阶段1) | Android `/sdcard` 浏览 | 浏览用户存储(`/sdcard`、SD 卡)目录;返回真实的名称/大小/类型/修改时间 | 列表内容与手机实际一致;大小与修改时间为真实值(非 0/非假);不同厂商/Android 版本下解析稳定 |
| P0(阶段2) | iOS AFC 沙盒浏览 | 在 AFC 能力边界内浏览沙盒(照片/DCIM 等);起点为 AFC 沙盒根(非 Unix `/`) | 可列出沙盒内容;不可达区域不被误展示为可写根目录 |
| P1(两阶段) | 手机文件缩略图 | 为手机上的图片/视频生成缩略图 | 图片/视频在列表/预览入口可见缩略图;不因缩略图失败阻塞浏览 |
| P1(两阶段) | 应用内预览(复用) | 复用现有文本/图片/音频/视频/PDF/ZIP 预览,直接预览手机文件 | 文本/图片/音视频/PDF/ZIP 手机文件可在应用内预览,无需先下载 |

#### 模块:文件操作(CRUD)
| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0(阶段1) | Android 增删改查 | 在 `/sdcard` 内新建目录、重命名、删除、读取(下载)、写入(上传)、复制、搜索(`find`) | 各操作真实生效并可验证;删除/改名对目录递归生效;搜索能定位匹配文件 |
| P0(阶段2) | iOS 增删改(受控) | 在 AFC 允许的范围内读取、写入、删除;对 AFC 不支持的结构性操作(建目录/改名等)返回明确错误 | 支持的操作真实生效;不支持的操作有可读的明确错误提示,且不残留半成品 |
| P1(两阶段) | 覆盖冲突处理 | 目标存在同名时询问覆盖/跳过/重命名 | 冲突时弹询问;不发生静默覆盖 |

#### 模块:跨设备传输
| 优先级 | 功能 | 业务行为 | 验收标准 |
|---|---|---|---|
| P0(两阶段) | 双向复制/移动 | 本地↔手机、手机↔SMB/SSH 远程双向复制与移动;多文件/目录批量;多设备同时连接 | 选中多文件/目录可批量复制/移动;同时连多台手机各自可操作;移动后源消失、复制后源保留 |
| P0(两阶段) | 传输进度与取消 | **流式**逐块传输;显示进度;支持中途取消;取消/失败清理目标端半成品 | 流式传输大文件不 OOM;进度可见;取消后目标端无半成品残留;失败不删源 |
| P1(两阶段) | 拖拽传输 | 支持桌面↔手机、面板↔面板拖拽传输 | 可用拖拽完成复制/移动(交互细节留给设计) |
| P2(阶段1) | Android 搜索增强 | 在 `/sdcard` 下按名称/模式搜索 | 能跨目录定位匹配项 |

### 8. 关键异常与失败结果

| 场景 | 异常 / 边界条件 | 期望业务结果 |
|---|---|---|
| 工具不可用 | `adb`/`libimobiledevice` 缺失或不可执行 | 对应平台禁用并给出原因;不崩溃、不空转 |
| Android 未授权 | USB 调试未放行(unauthorized) | 设备列出但标"待授权"并引导;操作被拒,原因明确 |
| iOS 未配对/配对失效 | 未信任或信任被撤回/过期 | 标"待配对"并提示重新配对;不静默失败 |
| AFC 能力边界 | 在沙盒只读/受限区做写/建目录/改名 | 返回明确"不支持"错误;不部分执行、不留残文件 |
| 传输中断 | 取消 / 断线 / 写入失败 | 清理目标端半成品;不删源;给出失败原因 |
| 覆盖冲突 | 目标已存在同名 | 询问,不静默覆盖 |
| 大文件 | 体积超过内存承载 | 采用**流式传输**逐块读写,不 OOM;极端情况(磁盘满/权限/断线)给出可读错误 |
| 中途状态变化 | 操作进行中拔线/撤回信任 | 当前操作以明确原因失败;设备状态降级;不留残 |

### 9. 非功能与领域约束

| 类别 | 约束 / 要求 | 状态 | 依据 / 风险 |
|---|---|---|---|
| 平台 | 聚焦 macOS(Electron 29 / Chromium 122);打包的工具须为 macOS 版 | 已确认 | 项目定位 macOS;Windows/Linux 不在本期范围 |
| 外部依赖 | `adb` + `libimobiledevice` **打包进安装包**随应用分发 | 已确认(用户决定) | packaging 管线**已存在**(electron-builder.yml + scripts/build-dmg.sh + `npm run dist:mac`);剩余工作是把两个工具加入 `extraResources` 并让 `MobileDeviceScanner` 解析打包内路径而非 `$PATH` |
| 许可/合规 | adb + libimobiledevice 打包分发;**不考虑** LGPL 等许可证合规义务 | 明确排除 | 用户决定:只要技术上可实现,不因许可证约束增加范围 |
| 安全/隐私 | 手机文件为用户个人数据;不收集不上传;配对信任关系仅本地 | 已确认 | 设备文件属敏感个人数据 |
| 数据安全 | 移动=复制成功后删源;失败绝不删源(R5) | 已确认 | 防手机端数据丢失 |
| 可靠性 | 配对/授权状态需**运行时**校验,不只启动时(R2) | 已确认 | 避免中途状态变化导致静默脏数据 |
| 性能/规模 | 大文件传输采用**流式**(逐块读写),避免内存占用过高 | 已确认 | 用户决定采用流式;纠正现有"读缓冲→写循环"模式 |
| 兼容性 | Android 厂商/版本 `ls`/`stat` 输出差异;iOS 不同版本 AFC 可写区差异 | 未决(需实测) | 直接影响解析稳定性与可写边界 |

### 10. 外部依赖

- **随应用分发的工具**:`adb`(Android 平台工具)、`libimobiledevice` 及其配套 CLI(`idevice_id`/`ideviceinfo`/`idevicepair` 及 AFC 访问能力)。
- **既有内部组件(复用)**:`MobileDeviceScanner`、`DeviceManager`、`FileOperationManager`(队列/进度)、`ThumbnailService`、各 `IFileSystemAdapter`、Preview 各类型预览组件、跨设备 `fs:copyBetween`/`fs:moveBetween`。

### 11. 明确不做(Out of scope)

- **不做** iOS 越狱/全文件系统访问:受众极小、风险高,AFC 沙盒已满足主场景。
- **不做** Android root/系统数据区(`/data`、`/system`)访问:需 root 且有变砖风险,`/sdcard` 已覆盖主流。
- **不做** 无线 ADB / Wi-Fi 传输:首版仅 USB。
- **不做** 双向目录同步:与手机文件(尤其 iOS 沙盒)语义冲突,复杂度高,YAGNI。
- **不做** 断点续传:与"取消即清理临时文件"语义冲突,以"手动重试"替代。
- **不做** 应用内自动安装工具:已决定改为打包分发。
- **不做** iMazing 式整机备份/恢复/应用管理:超出"文件管理"范围。
- **不做** MTP 协议直连:走 ADB shell 路径。
- **不做** 非 macOS 平台、多成员权限/审计。

### 12. 假设、风险与未决问题

#### 12.1 未验证假设
- **假设1**:Android 起始浏览路径为 `/sdcard`(用户存储根),含内部存储用户区与 SD 卡。若厂商把主存储挂在他处,会影响"默认入口";不成立则需调整默认根路径。
- **假设2**:iOS 起始浏览为 AFC 沙盒根(含 DCIM/PhotoData 等公开区),**不是** Unix `/`。若某些 iOS 版本沙盒根结构不同,会影响默认展示。
- **假设3**:覆盖冲突沿用现有文件操作的"询问覆盖/跳过/重命名"语义。若现有实现无此机制,则需补。
- **假设4**:设备拔插/授权/配对状态变化由现有 3 秒轮询及时捕获。若轮询间隔过长会影响"自动恢复可浏览"的体验。

#### 12.2 已知风险
- **打包管线已存在,工具打包待接线**:packaging 管线(`electron-builder.yml` + `scripts/build-dmg.sh` + `npm run dist:mac`)已就绪(需求澄清初期据 stale 快照误判为"无打包步骤",已据实修正);剩余工作是把 `adb` + `libimobiledevice` 二进制加入 `extraResources`、并让 `MobileDeviceScanner` 解析打包内路径(现走 `which`/`$PATH`)。另有"获取 macOS 版工具二进制(arm64/x86_64)"的取数工作。
- **AFC 能力边界不确定**:不同 iOS 版本可写区域不同,需实测,否则"受控写入"范围会与预期不符。
- **Android 解析脆弱**:厂商/版本 `ls -la`/`stat` 格式差异,现有解析(且 shell 返回值处理有误)易碎,直接威胁"浏览稳定"。
- **现有 `AndroidAdapter` 选型问题**:它依赖未安装的 `adbkit`,而 `MobileDeviceScanner` 已能直接走 `adb` CLI 发现设备——是继续用 adbkit、还是统一改走 adb CLI——**已决定采用 adbkit**(见下条)。
- **adbkit 接线工作量(已决定用 adbkit)**:原版 `adbkit` 约 2018 年后停更、且当前未安装;采用它需:加为真实依赖(建议维护版 fork `@devicefarmer/adbkit` 并核实 Node/Electron 29 兼容)、修现有"把流当字符串"的 API 误用(改用 `adbkit.util.readAll`)、补 stat/时间戳真实解析。**注意**:adbkit 经 adb server 工作,打包的 `adb` 仍负责提供 server,二者并存。具体 fork/版本待技术方案确认。

#### 12.3 未决问题
